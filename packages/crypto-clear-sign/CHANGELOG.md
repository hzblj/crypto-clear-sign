## 0.1.0

### Minor Changes

- [`985b3d6`](https://github.com/hzblj/crypto-clear-sign/commit/985b3d6deedfc078e17cfa86a7dc65769da0889c) Thanks [@hzblj](https://github.com/hzblj)! - Clear signing as data, in a package of its own. `@hzblj/crypto-clear-sign` is the display model every chain package returns and every UI renders: a `ClearSigning` with the chain (a CAIP-2 id), what is signed (`transaction`, `typed-data`, `message`, `offchain-message`, `psbt`, `authorization`), an intent and a summary, ordered fields of ten kinds (amounts as exact `bigint`s with decimals, symbol and an `unlimited` flag; addresses with their relation to the signer; moments that know whether they passed; durations, raw bytes, percentages, numbers, booleans, lists), nested actions for multicalls, batches, instructions and outputs, the source of the understanding (a built-in decoder, a descriptor with its id, or nothing), and the raw remainder. Warnings carry stable codes (twelve shared ones, from `UNLIMITED_APPROVAL` and `ASSET_OWNERSHIP_TRANSFER` to `RESOLVER_FAILED`; chain packages add namespaced codes with `defineWarnings`) and five severities, and risk is computed, never set: the most serious warning at and below each action. Every word is a `DisplayText` with a grouped code (`intent.approve`, `label.amount`), English and params, so `localize` translates by code. `createClearSigning` checks a result against the model and freezes it; the field constructors, `formatAmount` (exact, with the unlimited sentinel), `maxUint`, `fromUnixSeconds`, `checkDeadline`, `hasHiddenCharacters` and `plainText` (the whole review as accessible text) are the helpers. Resolvers for tokens, names and the address book, descriptors and the clock are interfaces the app plugs in, sync or async, none required; `createResolverContext` checks their answers, caches lookups and turns failures into `RESOLVER_FAILED`. Pure TypeScript with no dependencies.

- [`1475f90`](https://github.com/hzblj/crypto-clear-sign/commit/1475f908df5a906ffe52e0388d4b6d9c32c45f4b) Thanks [@hzblj](https://github.com/hzblj)! - Moments that are not deadlines, and resolver failures a chain package finds itself. `dateTimeField({deadline: false, value})` makes a `datetime` field that is never `expired` (an issue time, a "valid from", a moment a descriptor names), with no clock needed; a deadline still takes `now`. The resolver context's `fail(name)` reports a failure the chain package detects on its own, such as a built-in token list standing in for an app resolver that threw, or a chain package's own resolver (declared with the new `ownResolvers` option, such as `assets` or `lookupTables`) that answered nonsense: `RESOLVER_FAILED` names it with the rest, the shared resolvers first. The docs now say that a chain package, not only the `names` resolver, may mark an address `own` (the signer's own token accounts, a transaction's change).
