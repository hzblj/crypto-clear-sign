Moments that are not deadlines, and resolver failures a chain package finds itself. `dateTimeField({deadline: false, value})` makes a `datetime` field that is never `expired` (an issue time, a "valid from", a moment a descriptor names), with no clock needed; a deadline still takes `now`. The resolver context's `fail(name)` reports a failure the chain package detects on its own, such as a built-in token list standing in for an app resolver that threw, or a chain package's own resolver (declared with the new `ownResolvers` option, such as `assets` or `lookupTables`) that answered nonsense: `RESOLVER_FAILED` names it with the rest, the shared resolvers first. The docs now say that a chain package, not only the `names` resolver, may mark an address `own` (the signer's own token accounts, a transaction's change).
